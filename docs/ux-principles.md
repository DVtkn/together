# UX Principles — правила проектирования Loop

## 1. 0-1-2 клики
**Правило:** Любое действие пользователя должно выполняться за 0, 1 или максимум 2 клика (тапа).
- **0 кликов:** контент сразу виден на экране при входе (например, стрик на экране Дом)
- **1 клик:** одно тап открывает нужный раздел (таб «Пара», «Свидание», «Психолог»)
- **2 клика:** навигация на второстепенный экран (настройки конкретного параметра)
**Запрет:** 3+ клика для базового действия — приводит к оттоку.

## 2. Один экран — одна задача
**Правило:** На любом экране пользователь должен понимать, какую задачу он может решить right now, не читая инструкции.
- Если задача требует больше одного шага — разбить на под-экраны с пошаговым прогресс-баром
- Примеры: инвайт на свидание (3 шага: вайб + место + дата/время), настройка.push (1 страница со всеми тумблерами)

## 3. Аккордеоны для редкого контента
**Правило:** Сортировка, фильтры, настройки, которые используются реже 1 раза в сессию — оборачивать в `<details>` / collapse component.
**Зачем:** Не тратить экранный spazio на permanente элементы. Пользователь раскрывает то, что ему нужно.

## 4. Горизонтальные скроллы там, где удобнее
**Правило:** Листания карточек (колоды близости, deck-questions), табов с изображениями — горизонтальный скролл плавным свайпом. Вертикальный скролл — для списков сообщений и длинного контента.

## 5. Точные заголовки
**Правило:** Заголовок страницы должен отвечать на вопрос «Где я и что здесь делаю?».
- **Плохо:** «Настройки», «Дом», «Профиль»
- **Хорошо:** «Настройки (темы Aurora/Ночь, push, GDPR)», «Центр дня», «Паспорт пары»
**Польза:** Пользователь сразу понимает контекст и действия, доступные на экране.

## 6. Инлайн-действия вместо перебросов
**Правило:** Действия, меняющие состояние (ответить на вопрос, поставить лайк, поставить метку, отправить инвайт) — делаться на текущем экране без перехода на новую страницу.
**Механика:** Post-отправка → toast-уведомление → обновление списка данных без перезагрузки страницы.

## 7. Touch-zone 44px
**Правиле:** Минимальный размер таповой зоны — 44×44 пикселя. Все кнопки, иконки, ссылки, поля ввода должны удовлетворять этому минимуму на всех устройствах (особенно iOS).

## 8. Error states are part of UX
**Правило:** Пустые состояния, ошибки валидации, таймауты — должны быть полезными и дружелюбными, а не просто «Ошибка 500».
- Пустое состояние: объяснить, что делать дальше (например, «Напишите первое сообщение — в паре тоже есть, о чём поболтать.»)
- Ошибка валидации: подсвечивать поле + показывать конкретную причину, а не общий текст

## 9. Persistent state across sessions
**Правило:** Пользователь должен возвращаться в то же состояние приложения, в котором был ушел ( streak,last read position, open modals). Использовать `localStorage` / IndexedDB для кросс-сессии state.

## 10. Accessibility is not optional
**Правило:** Контрастность >= 4.5:1, focus outlines, aria-labels на иконках, поддержка VoiceOver на iOS. a11y — часть качества, а не чекбокс.

## How to apply these principles when tasking the agent

- Every task should reference which principle(s) it satisfies
- Acceptance criteria must verify the principle (e.g., "Button tap target is 44×44px" for Principle 7)
- If a trade-off is needed, document which principle is being compromised and why
