# PRD: Together — парное приложение с ИИ-психологом

> **Objective**: Приложение для пар: вместе проходить опросники по совместимости, получать совместный отчёт, отслеживать «пульс» отношений неделями, выполнять челленджи, вести базу знаний о партнёре (настроение, хотелки, цветы, виш-лист), находить места для свиданий и общаться с ИИ-психологом, который помнит контекст пары.

> **Статус**: **Beta v0.1.0** — первая бета-версия сайта. Релиз: `v0.1.0-beta` на GitHub. Основной функционал реализован и развёрнут; известны незакрытые пункты (см. раздел 8 — Definition of Done).

---

## 1. Проблема и гипотеза

### Проблема
Парам сложно:
1. **Говорить о чувствах системно** — разговоры о близости и конфликтах откладываются «на потом».
2. **Понимать друг друга** — различия в стиле привязанности, языках любви, ценностях часто выясняются больно, в ссоре.
3. **Не угадывать** — что подарить, куда пойти, что партнёр хочет по мелочи (шоколадка, цветы, книга).

### Гипотеза
*Если дать паре простой ритуал (опросники → отчёт, недельный пульс → челленджи), а также «базу знаний о партнёре» и персонального ИИ-помощника — пары станут ближе, начнут говорить о важном и меньше ссориться из-за недопонимания.*

## 2. Целевая аудитория

| Сегмент | Боль | Решение |
|---------|------|---------|
| Пары «на старте» (0–2 года) | Не знают друг друга глубоко | Опросники, совместный отчёт, база знаний |
| Пары в рутине (2+ лет) | Близость снижается, ссоры по мелочам | Пульс недели, челленджи, ИИ-советы |
| Пары с различиями в коммуникации | Привязанность/конфликты | Метод Готтмана, теория привязанности, ИИ-психолог |

## 3. MVP Scope

### MUST HAVE
- **Регистрация/вход**: логин + пароль (bcrypt), NextAuth JWT, Google OAuth (опционально).
- **Пара**: привязка по логину партнёра, статус PENDING/ACTIVE, выход из пары.
- **Опросники (5)**: стиль привязанности, 5 языков любви, конфликты (Готтман), ценности, Big Five. Отдельные ответы, приватные вопросы не показываются партнёру.
- **Совместный отчёт**: радар по 6 осям, сильные стороны, зоны роста, рекомендации; генерируется автоматически, когда оба прошли все опросники.
- **Пульс недели**: близость (1–10), конструктивность конфликтов (1–10), комментарий; динамика.
- **Челленджи недели**: создаются из пульса, выполняются обоими, история.
- **База знаний о партнёре**: настроение (emoji + текст), хотелки-мелочи (взял/не взял), любимые цветы, виш-лист (подарено).
- **Места (свидания)**: выбор города, фильтры по типу/цене/поиску, романтичные места.
- **Инвайт на свидание**: по прототипу — инициатор отправляет инвайт, получатель выбирает вайб/место/дату/время, инициатор получает готовый план с контактами места. Статусы: PENDING → PROPOSED.
- **ИИ-психолог**: диалоги с историей (сохраняются в БД), помнит контекст пары, кризис → направляет к специалисту. Провайдер: Groq (OpenAI-совместимый), резерв — OpenRouter.
- **Настройки**: имя, город, уведомления (push/email), удаление аккаунта, экспорт данных (GDPR/152-ФЗ).

### SHOULD HAVE
- Push-уведомления (Web Push + VAPID), подписки.
- Ресурсы кризисной помощи (телефоны горячих линий).
- Dark mode (есть).
- Расширенная библиотека тестов: уровни глубины, достижения, категории карты совместимости (см. Раздел 5).

### NOT IN MVP
- Психотерапевтические услуги, диагнозы, медицина.

## 5. Расширенная библиотека психологических тестов

> Дополнение к PRD: каталог тестов и система прогрессии. Входит в раздел функциональных требований (FR-12).

### 5.1. Концепция библиотеки тестов

Библиотека строится по принципу **«слоёв глубины»**: каждая пара начинает с базового теста и постепенно открывает более глубокие и специализированные опросники. Чем больше тестов пройдено, тем детальнее становится карта совместимости и точнее рекомендации ИИ.

```
Уровень 1: Знакомство        → 1 тест  → Общая карта
Уровень 2: Понимание         → 3 теста → 4 новые категории
Уровень 3: Глубина           → 5 тестов → 6 новых категорий
Уровень 4: Мастерство        → 8 тестов → Полная карта + персональный психологический портрет
Уровень 5: Исследование      → 12+ тестов → Экспертные инсайты и прогнозы
```

**Ключевой принцип:** Каждый тест добавляет данные в определённую категорию карты совместимости. ИИ использует накопленные данные для более точных рекомендаций и распознавания паттернов.

### 5.2. Система прогрессии и геймификации

#### 5.2.1. Уровни глубины пары

| Уровень | Название | Требуемые тесты | Награда |
|---|---|---|---|
| 1 | Знакомство | Базовый тест | Общая карта совместимости |
| 2 | Понимание | 3 любых теста | Категория «Привязанность» + значок |
| 3 | Глубина | 5 тестов, включая 1 глубинный | Категория «Сценарии детства» + совместный дневник |
| 4 | Мастерство | 8 тестов, включая 2 креативных | Полный психологический портрет пары |
| 5 | Исследование | 12 тестов | Прогноз динамики + приоритетная поддержка |

#### 5.2.2. Достижения (Achievements)

| ID | Достижение | Условие |
|---|---|---|
| ACH-01 | «Первый шаг» | Пройден первый тест |
| ACH-02 | «Синхронизация» | Совпадение ответов ≥ 80% в одном тесте |
| ACH-03 | «Полярность» | Совпадение ответов ≤ 30% — и пара прошла обсуждение в чате |
| ACH-04 | «Коллекционер» | Пройдено 5 тестов |
| ACH-05 | «Исследователь глубин» | Пройден тест из категории «Глубинные» |
| ACH-06 | «Игровая пара» | Пройдено 3 креативных теста |
| ACH-07 | «Год вместе» | 12 месяцев активности в приложении |
| ACH-08 | «Открытая книга» | Оба партнёра прошли все тесты уровня |

#### 5.2.3. Визуализация прогресса

- **Карта изученности пары:** силуэт пары, который постепенно заполняется цветом по мере прохождения тестов. Пустые зоны = неизученные категории.
- **Прогресс-бар уровня:** отображение до следующего уровня глубины.
- **Ежемесячный отчёт:** «В этом месяце вы узнали друг друга на 12% лучше».

### 5.7. Технические требования

#### 5.7.1. Модель данных

```sql
-- Тесты
CREATE TABLE tests (
  id UUID PRIMARY KEY,
  slug VARCHAR(50) UNIQUE,
  title VARCHAR(255),
  description TEXT,
  category VARCHAR(50),
  methodology VARCHAR(50), -- 'scientific', 'creative', 'deep'
  question_count INT,
  estimated_minutes INT,
  unlock_level INT DEFAULT 1,
  is_active BOOLEAN DEFAULT true
);

-- Вопросы
CREATE TABLE test_questions (
  id UUID PRIMARY KEY,
  test_id UUID REFERENCES tests(id),
  text TEXT,
  type VARCHAR(20), -- 'single', 'multiple', 'scale', 'image_choice'
  options JSONB,
  order_index INT
);

-- Результаты
CREATE TABLE test_results (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  test_id UUID REFERENCES tests(id),
  answers JSONB,
  scores JSONB, -- { "attachment_anxiety": 65, ... }
  completed_at TIMESTAMP
);

-- Карта пары (агрегированные данные)
CREATE TABLE couple_maps (
  id UUID PRIMARY KEY,
  couple_id UUID REFERENCES couples(id),
  category VARCHAR(50),
  score INT,
  details JSONB,
  updated_at TIMESTAMP
);
```

#### 5.7.2. Логика подсчёта

```typescript
interface TestScoring {
  // Каждый тест возвращает баллы по своим субшкалам
  subscales: Record<string, number>;

  // Маппинг субшкал на категории карты
  categoryMapping: Record<string, string[]>;

  // Вес теста в категории (0.0 - 1.0)
  weight: number;
}

// Пример: тест привязанности
const attachmentScoring: TestScoring = {
  subscales: {
    anxiety: 65,
    avoidance: 30,
    security: 70
  },
  categoryMapping: {
    anxiety: ['attachment', 'communication'],
    avoidance: ['attachment', 'conflicts'],
    security: ['attachment', 'intimacy']
  },
  weight: 0.8
};
```

### 5.8. UX-требования к прохождению тестов

| Требование | Описание |
|---|---|
| **Прогресс внутри теста** | Индикатор «Вопрос 3 из 12» + процент заполнения |
| **Возможность паузы** | Сохранение прогресса, можно вернуться позже |
| **Адаптивные вопросы** | Если пользователь отвечает «Затрудняюсь», предложить упрощённую формулировку |
| **Предупреждения** | Для глубинных тестов: «Этот тест может вызвать сильные эмоции» |
| **Пропуск вопросов** | Для деликатных тем — возможность пропустить без штрафа |
| **Результат сразу** | По завершении — экран с ключевыми выводами, не требующий перехода в другой раздел |
| **Обсуждение результата** | Кнопка «Обсудить с партнёром» → переход в совместный чат с контекстом |
